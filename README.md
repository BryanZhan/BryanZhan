# 你好，我是 Bryan Zhan 👋

**微结构图像处理** —— 把显微视野里的微观组织，变成能计算、能对比、能复现的数据。

我做的事可以概括成一句话：从原始显微图像出发，把分割、测量、统计、输出报告这整条链路做通。比起单张图「看起来对不对」，我更在意一套流程跑一大批图时，结果稳不稳定、说不说得清。

## 我在做什么

- **相与颗粒的分割** —— 把多相混杂的显微图像拆成可测量的对象，正面处理粘连、明暗不均、边界模糊这些真实样本里躲不掉的问题
- **定量统计与表征** —— 粒度分布、面积分数、形状因子、颗粒之间的共生与解离关系，把「看到的结构」翻译成能进表格、能进模型的数字
- **批处理流水线** —— 批量导入、自动分析、结果汇总、报告生成，让分析从「人工逐张点」变成「一键跑完再复核」
- **可视化与复核工具** —— 让每个数字都能回溯到图上的对应像素，算法出错时人能一眼看出来

## 深度学习在这里怎么用

语义分割、小样本与弱监督、域适应、超分辨、数据增强。我的态度是：它不是用来替代传统方法的，而是用来补上阈值法和形态学做不了的那部分场景——能用手工算法稳定解决的，就不硬套模型。

## 关注的技术问题

- 显微图像的**照明不均与拼接**，以及跨设备、跨批次结果的一致性
- **少标注**条件下的分割：怎么用尽量少的标注，把一批新样本类型接进流程
- 分割结果的**可复现性与评价指标**：同一批图换个人跑，结果应该一样
- 从单张图的分析，走向**整条流程的工程化**：性能、日志、异常处理、结果可追溯

`Python` · `NumPy` · `OpenCV` · `scikit-image` · `SciPy` · `PyTorch` · `Matplotlib`

## 我的一点工作方式

先把「要测什么、误差从哪来」定义清楚，再谈选什么算法。微观分析的难点通常不在于模型够不够新，而在于样本本身的复杂度，以及评价标准有没有说清楚。
